# Vue 3 + TypeScript + Vite

This template should help get you started developing with Vue 3 and TypeScript in Vite. The template uses Vue 3 `<script setup>` SFCs, check out the [script setup docs](https://v3.vuejs.org/api/sfc-script-setup.html#sfc-script-setup) to learn more.

Learn more about the recommended Project Setup and IDE Support in the [Vue Docs TypeScript Guide](https://vuejs.org/guide/typescript/overview.html#project-setup).

## 接口与登录基础层

- `src/utils/request.ts` 是项目默认请求入口；`httpClient.ts` 负责凭证、错误处理和 HTTP 响应解包。返回值仍是响应体，不额外包装或递归解包业务数据。
- 请求配置支持 Axios 的参数、请求头、取消信号及下载类型。`skipAuth` 用于公开认证接口；`silentError` 表示由页面自行显示错误。
- `src/utils/apiError.ts` 统一解析后端文本、`message`、验证错误和 ProblemDetails。表单使用 `getErrorMessage`，全局通知通过现有总线显示。
- `src/stores/user.ts` 统一管理登录、退出、用户资料和权限。页面读取 `isLoggedIn`、`userInfo`、`userId`；通过 `login`、`logout`、`setUser` 更新状态，不直接操作登录缓存。
- `fetchUserInfo(true)` 强制刷新资料，并复用进行中的请求。当前 `/User/me` 不返回 ID 和权限，因此刷新时会保留登录接口提供的身份字段。
- `src/router/auth.ts` 统一处理会话失效并跳转 `/LoginRegister`。登录成功和其他标签页切换账号时重新加载页面，清理已有业务缓存。
- `src/utils/authStorage.ts` 保留既有缓存键，负责持久化和容错读取；退出会清理全部身份字段。

### 回归检查

## 世界观模块

- `src/api/types/world.ts` 集中声明与后端对应的 DTO。卡片摘要携带关系数量，详情携带关系列表；表单通过独立的 `CardForm` 类型表达可编辑状态。
- `src/api/worldApi.ts` 直接返回 DTO，调用方不再读取额外的 `.data`；删除接口返回 `Promise<void>`。现有 HTTP 路径、请求字段及后端 JSON 字段保持兼容。
- `src/stores/world.ts` 按项目保存项目资料、卡片摘要及关系快照，详情按项目和卡片 ID 缓存，空列表也可命中缓存。`fetchCards(id, true)` 显式刷新；写操作使关联缓存失效并重新读取当前项目。
- `fetchCardDetail` 选择主详情；`loadCardDetail` 用于嵌入卡片和图谱预加载，两者复用详情缓存。后台加载不会改变当前选中的卡片。`fetchCardsByIds` 返回全部请求项并保留输入顺序。
- `useAsyncRequests` 只合并进行中的同类请求，失效后忽略旧响应。Store 为每个实例维护独立缓存，账号变化时清空；分别提供项目列表、公开列表、卡片列表、详情和保存状态，避免并发请求互相提前关闭加载状态。
- 卡片保存与关系差异同步由 Store 统一负责，修改关系类型也会同步。多步保存中途失败后仍刷新服务端状态；写入成功后的刷新失败不会被当成写入失败，以免重复提交。
- 后端 `WorldRelationMapper` 复用关系 DTO 的实体映射与查询投影，`WorldCache` 集中处理卡片及项目列表缓存失效。卡片改名、删除或关系变化会清理受影响的卡片缓存；详情命中缓存前仍校验访问权限。

## 世界观后端职责与接口约定

- `Controllers/World` 只负责绑定请求和构造 HTTP 响应；项目创建/删除的配额编排、卡片创建配额以及卡片类型 CRUD 均由服务负责。
- `WorldControllerBase` 统一解析当前用户 ID，缺失或无效身份返回 401；匿名读取端点不要求解析身份。`WorldAccess` 统一公开/私有读取和所有者写入规则，关系查询在服务内检查访问权限。
- 修改、删除卡片会校验 URL 中的项目归属；删除关系要求 URL 中的卡片属于关系任一端，且调用者为源卡片项目的所有者。删除项目时先清理受 Restrict 外键约束的双向关系，再删除项目并清理缓存。
- DTO 的 DataAnnotations 统一约束长度和枚举，HTTP 请求沿用 `[ApiController]` 的自动 400 校验，直接调用服务时通过 `WorldValidation` 复用约束。更新字段的空值语义、空关系名称和 `limit=0` 保持兼容；负数历史条数及无效扩容枚举提前拒绝。
- `WorldOperationException` 表达预期业务失败；世界观异常过滤器统一映射为 400/401/403/404/409。权限拒绝不再使用把消息当作认证方案的 `Forbid(message)`。未预期异常继续由原有全局过滤器处理，其他模块的行为不变。
- 成功响应保持原有路径、DTO 字段、201/Location 和空 204；配额失败保留 `QUOTA_EXCEEDED`、`CARD_LIMIT_EXCEEDED` 及计数字段，参数失败保留 `errors` 格式，卡片类型列表保留其原有 500 格式。
- 卡片类型仅两个 GET 端点允许匿名，写接口要求 `Admin`。系统类型规则以原控制器为准：不能修改 Label、不能删除；图标、描述、排序和启用状态仍可更新。旧的未接入服务与控制器规则冲突已消除。
- `WorldProjectMapper` 合并重复投影，项目摘要通过 SQL 计数获取卡片数量，不加载完整卡片集合。项目增删与配额计数目前仍沿用原有分步保存，未在本批改为事务或数据库级配额锁。

后端检查覆盖 HTTP 契约、匿名/管理员权限、错误映射、DTO 校验、项目访问规则和 SQL 翻译；不等同于真实数据库端到端测试。
